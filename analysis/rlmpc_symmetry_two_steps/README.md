本次修改改善行走時左右落腳偏差，並將正常停止改為「完成原有擺腿 → 零速兩步回位 → STAND」。375 維輸入、8 維輸出、policy／MPC 50 Hz、控制 100 Hz、0.5 秒步態週期均保留。

後續已收緊轉彎／側移補償，最新限制與測試見 [轉彎與側移修正](turning_correction.md)。下文保存第一版修改與當時的驗證結果。

直行時，左右前腳與左右後腳分別共用平均 X 補償，Y 補償取鏡像。一個完整週期使用同一次取樣，避免左右腳相隔半週期鎖定不同補償。轉彎與側移保留獨立補償。新增訓練 penalty（權重 -0.1）讓 policy 學習此對稱關係，既有偏移幅度 penalty 仍在。這是對 residual 的限制，不是強制不同相位的實際腳位置相等，也不能保證所有地形、擾動下的實際姿態完全對稱。

「兩步」定義為兩組對角腳各一次：FL/HR → FR/HL。停止後先完成當前擺腿與減速，再以精確零速度指令讓兩組腳回到初始站姿的 XY 足端目標。這段不使用 RL 偏移，仍有接觸回饋與向下搜尋。每組名義擺腿 0.25 秒，接觸確認、減速與地形搜尋會使總停止時間大於 0.5 秒。重新收到行走指令時，先完成正在執行的落地；初始 STAND 與站立失去接觸的恢復流程不額外啟動兩步。

MJLab 訓練與 Python 控制器已啟用；Rust 部署的 `mjlab_foot_state_history_v3` 同步修改，舊 profile 保留原流程。沒有更換或重新訓練 checkpoint，也沒有啟動機器人的控制程序。

使用同一份 `2026-09-09_15-00-51/model_9999.pt`、平地、固定初始狀態比較：站立 2 秒，0.2 m/s 直行 6 秒，停止 4 秒。行走後 4 秒每隻腳各取 8 次由 swing 轉到 stance 的足端 X，避免將不同相位的瞬間位置混為一談；停止姿態統計最後 2 秒的 12 關節 RMSE。

實測確認原本右後腳持續偏前，不只是 trot 正常的瞬間相位差。新控制下的後腳平均落地差大幅縮小；停止姿態也改善，但剩餘約 3° 關節 RMSE，不能稱為完全回到零誤差。模型未重新訓練，因此不能將改善歸功於新的 reward。

另有 3 秒站立、10 秒直行、7 秒停止的三環境測試，完整結果在 `deterministic_eval.json`。新控制＋最新模型在平地的停止 RMSE 約 0.0492 rad；level 3 的平地、隨機起伏、低波浪約為 0.0492、0.1008、0.0480 rad，皆完成並四脚站穩。這些是固定 seed 的短程回歸，不代表多指令或擾動下的全面通過。

驗證包括 Python 相關單元測試、型別與 lint 檢查，及 Rust runner／locomotion 測試。Rust 的 `full_policy_pipeline_with_onnx` 有既有預設模型不相容：模型是 74 維、預設 profile 預期 71 維，因 fallback 到純 MPC 而使 inference 次數斷言失敗；保留原模型與測試，相關 runner 測試另外排除此項執行。此次 v3 的新增測試不依賴該模型。
